Extract today's focus tasks from a voice transcript. Output ONE JSON object only.

Schema:
{"containsActionableTasks":bool,"selectedTasks":[...],"extraCandidates":[...],"detectedMoreThanThree":bool}

WHAT GOES IN EACH FIELD:
- selectedTasks: tasks 1, 2, 3 (in spoken order). Max 3.
- extraCandidates: tasks 4, 5, ... ONLY if more than 3 distinct surviving tasks. Otherwise [].
- detectedMoreThanThree: true iff >3 surviving distinct tasks.
- containsActionableTasks: false iff transcript is filler/mic-test/no-task.

CRITICAL: extraCandidates is NEVER for cancelled tasks, duplicate wordings, or things you are unsure about. Those simply DO NOT appear anywhere in the output.

PROCESS (do not show your work):
1. List every task the user actually said, in spoken order.
2. DELETE cancelled tasks: any task immediately before phrases like "never mind", "wait never mind", "scratch that", "actually no", "wait no", "cancel that", "skip X", "not X Y instead", "almost said X but not today" — gone, not in any field. The replacement task takes its place.
3. DELETE duplicate wordings: "email Sam" and "send Sam an email" mean the same action — keep the cleanest wording ONCE.
4. COLLAPSE substeps: if user names a parent task then lists its steps, output the parent ONLY ("launch email: subject, body, send" → "finish launch email", not three tasks).
5. Count what remains. If ≤3, selectedTasks=all, extraCandidates=[]. If >3, selectedTasks=first 3, extraCandidates=rest.

VAGUE BUT STATED ARE VALID TASKS:
- "Deal with taxes", "handle tax stuff", "figure out apartment" — keep AS STATED. These ARE tasks. Do NOT set containsActionableTasks=false just because the wording is vague.
- Do NOT over-specify ("figure out taxes" stays "figure out taxes", not "file tax return").

ALSO:
- No inference. "Call the doctor" ≠ "schedule appointment".
- Future-day tasks ("tomorrow", "next week") excluded UNLESS framed as "prepare today for tomorrow".
- "Don't X" / "stay off X" / "avoid X" — VALID task, keep negative phrasing.
